# Product Requirements

Structured requirements for FitVibe. **IDs `FR-001` / `NFR-001` (and `REQ-…`) in `a.Requirements/` are the single source of truth.** Narrative summaries in [`1.Product_Requirements_Document.md`](./1.Product_Requirements_Document.md) map onto those IDs; they are not a second numbering scheme.

| Folder                                                     | Contents                                            |
| ---------------------------------------------------------- | --------------------------------------------------- |
| [`a.Requirements/`](./a.Requirements/)                     | Functional and non-functional requirements          |
| [`b.Epics/`](./b.Epics/)                                   | Epics                                               |
| [`c.Activities/`](./c.Activities/)                         | Implementation activities                           |
| [`d.User_stories/`](./d.User_stories/)                     | User stories                                        |
| [`e.Acceptance_Criteria/`](./e.Acceptance_Criteria/)       | Acceptance criteria (SSOT for ACs)                  |
| [`Requirements_Catalogue.md`](./Requirements_Catalogue.md) | Catalogue with links into `a.Requirements/`         |
| [`rtm_comprehensive.csv`](./rtm_comprehensive.csv)         | Legacy RTM (see [`rtm_README.md`](./rtm_README.md)) |

Statuses: **Open**, **Progressing**, **Done**. Keep each folder `INDEX.md` in sync with file headers (regenerate with `docs/_sync_docs.py`).
